# RemoteSnapshots native candidate review

Reviewed 2026-10-27 against the preserved dirty tree and the authoritative create contract.

## Disposition

Do not land the candidate as a provider resource yet. The native transport projection is a useful implementation slice, but the registered resource is not contract-qualified as a Terraform managed resource.

## Concrete findings

1. `remoteSnapshotResource.Metadata` does not set `response.TypeName`, so the registered resource is not fully described to the Framework.
2. `Read` is an empty method. A managed resource that cannot refresh state cannot distinguish a completed remote snapshot, a missing object, or a transient API failure.
3. `Delete` and `Update` always return diagnostics. This leaves a created Terraform state object that cannot complete normal lifecycle operations.
4. `ImportState` accepts an ID even though no read contract exists to populate or validate the imported object.
5. `location` is validated as a generic DNS label, not against configured destination aliases. The create contract requires a configured writable destination alias; accepting arbitrary labels would fabricate supported behavior.
6. The only offline test exercises one Basic-auth POST and one response. It does not qualify bare versus batch request projection, default location omission, response-only `drive_meta`, cancellation and timeout classification, redirects, unknown outcomes, or malformed/partial response handling.

## Smallest native extension required

Before registering a full managed resource, add a provider-owned RemoteSnapshots service with:

- an explicit configured-location alias resolver that distinguishes omitted default from an invalid destination;
- request projection tests for UUID and minimal nested drive references, with `drive_meta` excluded;
- a response decoder that preserves ordered `objects` results and classifies redirect, cancellation, timeout, and unknown outcomes without leaking response bodies;
- documented GET-by-UUID and DELETE semantics, including 404/missing-object behavior and whether deletion is acknowledged or terminal;
- only then, a resource implementation with `Metadata`, `Read`, `Delete`, and import behavior backed by those contracts.

Until those API semantics are supplied and qualified, the smallest honest delivery is the native POST transport plus a blocker report; registering a create-only resource would be misleading.

The original candidate report and all prior verification receipts remain unchanged.
